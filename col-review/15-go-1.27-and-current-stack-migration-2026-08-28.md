Date: **2026-08-28**

Branch: **codex/quarry-tool-sync**

Committed baseline: **70e34eafc59f76c89422c3b32d8e912321c0be93**

Status: **migration implemented and locally validated; public release remains frozen**

## Decision

Novera now requires Go 1.27 and uses the current stable/LTS toolchain where the
project can validate it honestly. The migration is more than a version bump:
new language/library APIs replaced duplicated persistence and job plumbing,
the frontend and CI toolchains moved together, current Wails assets were
reviewed, cross-compilers were proven on four targets, and the experimental
Android build received a bounded modern-toolchain/security pass.

Dropping older platforms was accepted where it unlocks a coherent supported
stack:

- macOS now requires 13 or later, matching Go 1.27;
- Linux packaging defaults to GTK 4 and WebKitGTK 6.0, targeting Ubuntu 24.04+
  or Debian 13+ rather than the legacy GTK 3 stack;
- the experimental Android build now requires API 24 or later.

This pass does not change the existing release freeze. Wails remains a beta,
native interactive/package validation and signing are still required, and the
Android mobile host still needs a dedicated Wails beta.15 synchronization and
security review.

## Go 1.27 benefits adopted

### Generic methods and promoted literals

Big-file job helpers are now private generic `FileService` methods instead of
package-level functions that take the service as their first argument. This
keeps generic job orchestration in the owning type's namespace and removed an
unused wrapper. SQL write/preview options use promoted embedded-field keys in
struct literals, eliminating redundant nested literals.

### Strict JSON v2 persistence

`internal/jsonsafe` now centralizes persisted/security-sensitive decoding on
`encoding/json/v2`. It rejects duplicate object names, invalid UTF-8, unknown
members, case variants, and trailing values. The explicit v1 merge option
preserves the established behavior where persisted `null` members leave
non-zero defaults intact.

That one helper replaced separate recursive duplicate-key walkers and decoder
plumbing in settings, artifacts, database profiles, and big-file recovery.
The `internal/` working-tree delta is **243 net lines smaller**, including new
regression tests. Go's release notes also state that v1 JSON is now backed by
the v2 implementation and that unmarshal is significantly faster.

### Cumulative current-toolchain helpers and modernizers

This migration also adopts useful APIs from recent Go releases that are now
available throughout the required Go 1.27 toolchain:

- `slices.Backward` (Go 1.23) replaces reverse-index loops.
- `strings.SplitSeq` and `strings.FieldsSeq` (Go 1.24) avoid temporary split
  slices in preview, search, replace, and SQL schema paths.
- The long-standing `bytes.LastIndexByte` replaces a local reverse byte scanner.
- `sync.WaitGroup.Go` (Go 1.25) replaces manual Add/go/Done sequences where
  ownership is exact.
- `errors.AsType` (Go 1.26) replaces repeated typed error boilerplate.
- At twelve suitable test sites, `httptest.NewTestServer` (Go 1.27) replaces
  explicit server-close cleanup and uses in-memory fake networking. Tests that
  intentionally exercise real loopback TCP remain on `httptest.NewServer`.
- `go fix` modernizers produced the embedded-literal, backward-slice,
  wait-group, and typed-error cleanups above. The Go 1.27 atomic and
  unsafe-helper modernizers were also run but found no applicable changes. A
  final `go fix -diff` is clean.

### Automatic runtime/library gains

No project code is needed to receive Go 1.27's size-specialized small
allocation path and faster JSON unmarshal. Go 1.27 also improves DEFLATE
compression, but Novera's current XLSX path is read-only: no XLSX-read speedup
is claimed, and the encoder gain would apply only to future ZIP/GZIP/PNG write
paths that use Go's compressor. The new `goroutineleak` profile is available
for diagnostics without adding a public debug endpoint.

The new experimental SIMD packages were not enabled: the API remains
experimental and this pass did not establish a portable, benchmark-backed
hotspot that justifies an experiment flag. The new standard UUID package was
also not forced into persisted identifiers; Novera has no direct UUID module
dependency to remove, and an identifier-format change would add migration risk
without reducing the current code.

## Wails and native build assets

The Go module, frontend runtime, CLI/workflow pin, documentation, generated
bindings, and native assets moved together to beta.15. Binding regeneration
added the existing audit `formatVersion` model field and updated comments; the
reviewed renderer-callable method allowlist did not expand.

Accepted generated-asset improvements include:

- GTK 4/WebKitGTK 6 Linux package dependencies;
- arm64-only iOS capability metadata and device/simulator-aware archive builds;
- unconditional iOS archive rebuilding to avoid stale native output;
- Windows NSIS per-user installation branches, available for a future explicit
  `WAILS_INSTALL_SCOPE=user` build but not selected or exercised by the current
  machine-scope default.

Wails beta.15 still generates a macOS 12 minimum. The build-asset task now runs
a fail-closed reconciler that restores macOS 13 in both plists. Table tests
cover current, missing, duplicate, non-string, and intervening-key cases, so an
upstream template-shape change fails instead of rewriting an unrelated value.
Novera's own Linux homepage and proprietary/no-license-grant metadata were
preserved during generation review.

Wails beta.15 is still explicitly a pre-release. Its release notes describe the
API as stable while warning that pre-final issues may remain; this pass retains
the existing runtime containment and release policy.

## Cross compilation

The cross image now uses Go 1.27.0, Zig 0.16.0, and macOS SDK 26.1 with pinned
SHA-256 values. A pre-`FROM` `TARGETPLATFORM` declaration was removed because
it shadowed BuildKit's automatic argument and made the documented build path
resolve an empty platform.

The image built normally and passed production CGO compilation for:

- macOS amd64 and arm64, both verified as Mach-O with minimum macOS 13.0.0;
- Windows amd64 and arm64, verified as PE32+ x86-64 and AArch64.

The pinned Darwin sysroot is SDK 26.1. Zig 0.16's external linker currently
records SDK 26.4.0 in `LC_BUILD_VERSION`, while preserving the required 13.0.0
minimum. Go 1.27's new `-macos` and `-macsdk` linker options are internal-link
only and were verified to have no effect on this required external CGO path;
ineffective flags were therefore not committed. Treat exact SDK load-command
alignment as a remaining release-evidence caveat, not as a validated claim.

## Android bounded migration

The experimental Android build now uses AGP 9.3.2, Gradle 9.7.1, Java 17,
compile SDK 37, target SDK 36, minimum SDK 24, Build Tools 37.0.0, NDK r29,
and current stable AndroidX/Material dependencies. Build and configuration
caches are enabled and were proven reusable.

The API-34 to API-36 behavior migration adds edge-to-edge insets and predictive
back handling. Cleartext traffic and application backups are disabled. The
legacy JavaScript bridge is limited to the exact `https://wails.localhost`
origin/default HTTPS port; every other WebView resource is rejected, including
iframe and POST paths that bypass normal navigation callbacks. External
top-level links open in the system browser. Renderer loss and teardown fail
closed, and dead MIME-detection code was removed.

The app compiles against API 37 but does not target it yet. Android 17 blocks
local-network access by default for target-37 apps unless they implement the
new runtime permission flow. Novera depends on LAN database/provider access and
does not yet have appropriate explanation, denial, and retry UX, so a generic
startup prompt was rejected. Target 36 meets the August 2026 Google Play
requirement. See [Android build status](../build/android/README.md),
[Google Play target requirements](https://developer.android.com/google/play/requirements/target-sdk),
and [Android local-network permission guidance](https://developer.android.com/privacy-and-security/local-network-permission).

The checked-in mobile host still predates Wails beta.15's expanded lifecycle,
dialog, file-picker, mobile API, main-thread, and Go-overlay integration. A
wholesale template import would add roughly 2,400 lines and packaging defaults
that conflict with Novera's fail-closed signing policy. Production Android
packaging therefore remains disabled pending a dedicated host/security
migration. The longer-term bridge should use an origin-scoped WebKit message
listener; Android documents that `addJavascriptInterface` is exposed to every
frame.

## Intentional holds and residual blockers

1. **TypeScript 7:** deferred until typescript-eslint publishes a compatible
   peer range; forcing it would leave an invalid dependency graph.
2. **Node 26 Current:** CI uses the latest Node 24 LTS instead of a non-LTS
   frontend build runtime.
3. **Experimental SIMD:** not enabled without a stable API and a measured
   portable hotspot.
4. **Android target 37:** requires a product-level local-network permission
   experience; target 36 is current-policy compliant.
5. **Android Wails host:** runtime/APK support remains unclaimed until the
   beta.15 host and origin-scoped bridge are reviewed and tested.
6. **Native release evidence:** Windows/macOS/Linux interactive launch,
   install/upgrade/uninstall, signing/notarization, accessibility, and clean-host
   tests remain required.
7. **Release publication:** remains deliberately disabled. Wails is still beta,
   the development executable is unsigned, and existing governance/license
   decisions are not resolved by a toolchain migration.
