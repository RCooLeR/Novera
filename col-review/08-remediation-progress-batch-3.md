The original 142 finding records remain the historical review of the tagged revision. All changes described here are still working-tree changes unless a later handoff explicitly records a commit.

- **Remediated in cited surfaces** means the concrete vulnerable paths now enforce the stated invariant and have adversarial regression coverage. It does not close a wider architecture cluster in unrelated services.
- **Strongly contained** means the dangerous behavior is blocked or made fail-closed, but a larger transactional, lifecycle, or recovery design remains outstanding.
- **Partially addressed** means risk was materially reduced without satisfying the complete roadmap acceptance criteria.

## Independent adversarial re-review and follow-up fixes

This batch used repeated read-only adversarial passes after the initial implementation. Those passes found and closed issues that ordinary happy-path tests did not expose:

1. **Agent admission and cancellation:** Start originally performed blocking settings/secret work before registering an admission attempt; cancel during unresolved Start/Send could later reinstall a stale ID; cancel released or classified state using context timing rather than the exact lease flag. The implementation now registers attempts first, uses attempt/session tokens, retains the lease through finalization, and classifies from the locked cancellation bit.
2. **Event delivery:** independent Wails handlers could deliver terminal events before prior content. Backend sequence numbers plus bounded frontend reorder queues now provide a deterministic run/request order and reject malformed/gapped overflow.
3. **Workspace transition settlement:** audits found stale ownership changes while Begin, End, Abort, Close, and rollback calls were awaiting. The final flow rechecks ownership after every settlement boundary, distinguishes whether the backend root mutation already committed, never restores an old transcript after a successful Close, clears renderer chat after irreversible stale End, and prevents an older catch from clearing a newer transition flag.
4. **Secret corruption classification:** a wrong but valid-length non-Windows master key was initially indistinguishable from ciphertext damage. V3 key fingerprints now identify the recovery condition before GCM Open without exposing key material.
5. **Secret migration recoverability and trust:** failed automatic copy originally detached metadata; a full store made migration deterministically fail; and worse, legacy refs could be rebound to attacker-edited scope metadata and later used. Automatic rebinding is now disabled. Legacy refs remain quarantined and point-of-use consumers reject them. Explicit re-entry performs a count-neutral atomic replacement and has deterministic restart recovery for the narrow secret-first commit window.
6. **Persistent-file fail-closed details:** follow-up review added case-insensitive duplicate-key detection, valid UTF-8 checks, semantic field/count limits, symlink/reparse/non-regular rejection, exact output-size validation, and published-vs-unpublished failure handling so compensation cannot undo an already visible commit.
